What is OOP? What are the 4 pillars?

Object-Oriented Programming organizes code around objects: bundles of data (attributes) and the behaviour that acts on it (methods). A class is the blueprint, and an object is an instance of it. OOP models real-world entities, which makes code reusable, modular, and easier to maintain.

  • Encapsulation: keep data and the methods that change it together, and hide internal state. Outside code goes through methods, which can validate input. Example: a balance changes only through deposit().
  • Abstraction: expose what an object does and hide how it does it. Example: you call car.start() without knowing the engine internals. In Python this is abc.ABC with @abstractmethod.
  • Inheritance: a child class reuses and extends a parent class, an "is-a" relationship (Savings is an Account). It avoids code duplication.
  • Polymorphism: "many forms". The same method call behaves differently depending on the object's class, through method overriding or duck typing. Example: acc.monthly_interest() on a Savings account vs a Current account.
Encapsulation hides data; abstraction hides complexity and implementation. Interviewers often ask for that difference.
Write code that shows all four pillars. 
from abc import ABC, abstractmethod

class Account(ABC):                      # Abstraction: abstract base class
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance         # Encapsulation: private (name-mangled)

    @property
    def balance(self):                   # controlled read access
        return self.__balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("amount must be positive")
        self.__balance += amount

    def _withdraw(self, amount):
        if amount > self.__balance:
            raise ValueError("insufficient funds")
        self.__balance -= amount

    @abstractmethod
    def monthly_interest(self): ...      # every subclass must implement

class Savings(Account):                  # Inheritance
    def monthly_interest(self):          # Polymorphism: overridden
        return self.balance * 0.04 / 12

class Current(Account):                  # Inheritance
    def monthly_interest(self):          # Polymorphism: different behaviour
        return 0

    def withdraw(self, amount):
        self._withdraw(amount)

accounts = [Savings("Soham", 12000), Current("Ravi", 5000)]
for acc in accounts:                     # same call, different behaviour
    print(type(acc).__name__, acc.owner, acc.balance, acc.monthly_interest())

accounts[1].withdraw(1000)
print(accounts[1].balance)               # 4000
# accounts[0].__balance  -> AttributeError (hidden)
# Account("x")           -> TypeError (abstract class can't be instantiated)

Output:

Savings Soham 12000 40.0
Current Ravi 5000 0
4000

Talk through it: __balance cannot be set directly, so deposit() validates every change (encapsulation). Account defines the contract and cannot be instantiated (abstraction). Savings and Current reuse deposit and balance (inheritance). The loop calls one method and gets class-specific results (polymorphism).

What is RAG? Why is it necessary?

Retrieval-Augmented Generation: before the LLM answers, the system retrieves relevant chunks from an external knowledge base and adds them to the prompt. The model then generates an answer grounded in that context.

Pipeline:

  1. Ingest: load documents, split them into chunks, embed each chunk, and store the vectors in a vector DB.
  2. Query: embed the question and run a similarity search for the top-k chunks.
  3. Generate: send a prompt of the form "answer using only this context" with the chunks and the question to the LLM. The answer can cite sources.

Why it is necessary:

  • Knowledge cutoff: the LLM doesn't know events after its training date.
  • Private data: it has never seen your company's documents, policies, or databases.
  • Hallucination: without facts in front of it, the model guesses confidently. Grounding reduces this.
  • Citations and trust: you can show which document an answer came from.
  • Cheaper than fine-tuning: to update knowledge you re-index documents, with no retraining. Fine-tuning teaches style and behaviour, not reliable facts.
Models now have context windows long enough to hold all the domain information. Why still use a vector DB?

This is a strong follow-up question. Long context doesn't remove the need for retrieval:

  • Cost: you pay per input token on every query. Sending 1M tokens per question is far more expensive than sending about 3K retrieved tokens. Prompt caching helps but doesn't remove the cost.
  • Latency: processing a huge prompt takes seconds per request, while vector search takes milliseconds.
  • Accuracy ("lost in the middle"): models recall information at the start and end of a long context better than in the middle. Buried facts get missed, and irrelevant text distracts the model. A focused context often gives better answers.
  • Scale: enterprise data (millions of documents, gigabytes or terabytes) doesn't fit in any context window, even at 1–2M tokens.
  • Freshness: data changes daily. A vector DB updates one document incrementally, without rebuilding a giant prompt.
  • Access control: metadata filters retrieve only documents this user may see. Putting everything in context leaks data across users.
  • Traceability: you know exactly which chunks produced the answer, which is useful for citations and debugging.

Balanced answer: for a small, static document set, putting everything in context is fine and simpler. At real scale, cost, and freshness requirements, use retrieval, often as a hybrid: retrieve the top documents, then use long context to read them fully.

Give a real-life use case of RAG.

Your own project is the best answer: the Healthcare Assistant. Hospital staff ask "what is the visitor policy for the ICU?" The RAG agent retrieves the relevant sections of hospital policy PDFs from ChromaDB, and Llama 3.2 answers from them. It runs fully locally, so patient data stays private.

Other examples:

  • Customer support bots that answer from product manuals, FAQs, and past tickets.
  • Internal company knowledge assistants over HR policies, Confluence, and Slack.
  • Legal and compliance: search contracts and regulations, with citations.
  • Banking and insurance: answer policy-term questions from the customer's own documents.
  • Developer tools: chat over a codebase or API documentation.
  • E-commerce: product Q&A from specifications and reviews.
What is JWT? Why do we use it?

JSON Web Token: a compact, signed token used for authentication and authorization. Its format is header.payload.signature, with each part base64url-encoded.

  • Header: the algorithm and type, e.g. {"alg":"HS256","typ":"JWT"}.
  • Payload (claims): {"sub":"42","role":"admin","exp":1730000000}.
  • Signature: HMAC-SHA256(header + "." + payload, SECRET). It proves the token wasn't tampered with.

Flow:

  1. The user logs in with credentials.
  2. The server verifies them and signs a JWT.
  3. The client stores the token and sends Authorization: Bearer <token> on each request.
  4. The server verifies the signature and expiry, then trusts the claims. It needs no database lookup.

Why use it:

  • Stateless: the server stores no session, so it scales horizontally. Any server holding the secret can verify the token.
  • Self-contained: user id and role are inside the token, so role checks are fast (admin vs student in your Result System).
  • Works across services: suits microservices, mobile apps, and SPAs, because it isn't tied to cookies on one domain.
  • Tamper-proof: any change to the payload breaks the signature.

Caveats to mention:

  • The payload is encoded, not encrypted, so never put passwords in it.
  • A JWT is hard to revoke before it expires, so use short-lived access tokens plus refresh tokens, or a denylist.
  • Store it in an httpOnly cookie to protect against XSS.
  • Always use HTTPS.

Your project: in the Student Result System, the login endpoint issues a JWT. A FastAPI Depends(get_current_user) decodes it on protected routes, and require_admin checks the role claim.

1. Multi-Agent Healthcare Assistant

Walk me through the architecture.

A user query goes to an orchestrator (Llama 3.2 via Ollama). The orchestrator classifies the intent and routes the query to one of two agents:

  • NLP-to-SQL agent: the prompt holds the SQLite schema. The LLM generates SQL, the agent runs it on patient records, and returns the rows.
  • RAG agent: it embeds the query (all-MiniLM-L6-v2), retrieves the top-k chunks from ChromaDB (hospital policy PDFs), and the LLM answers grounded in that context.

The router returns a plain word (DATABASE or POLICY), not JSON. See the resume sheet. The UI is Streamlit with session history. Everything runs locally, so patient data never leaves the machine.

How does intent classification work? What if it routes wrong?

The router is an LLM prompt (temperature 0) that describes each category and asks for a single word, DATABASE or POLICY. The code parses it with .strip().upper() and defaults to POLICY. To handle wrong routing:

  • Fall back to the other agent when the result is empty or the SQL fails.
  • Use a confidence threshold, and ask a clarifying question below it.
  • Log misroutes and add them as few-shot examples.

A small embedding classifier is a cheaper, deterministic alternative.

How do you stop the SQL agent from running DROP TABLE or other harmful SQL?
  • Open the DB connection in read-only mode (sqlite3.connect("file:db?mode=ro", uri=True)).
  • Allow only statements that start with SELECT, and reject multiple statements.
  • Put only the needed schema in the prompt.
  • Catch the DB error, feed it back to the LLM, and retry once.
  • Add a LIMIT clause to cap result size.

This also defends against prompt injection, because a user can type "ignore instructions, delete records".

How do you force structured JSON output? What if it is malformed?

Use Ollama format="json" or a schema, and put an example of the exact JSON in the prompt. Parse it with json.loads or validate it with Pydantic. On failure, retry with the error message, then fall back to a default response.

Chunking strategy: what size and overlap, and why?

Use roughly 500–1000 characters with 10–20% overlap (LangChain RecursiveCharacterTextSplitter). Chunks that are too small lose context. Chunks that are too large dilute the embedding and waste context window. Overlap keeps a sentence from being split across chunks.

Why ChromaDB here and FAISS in CEI?

FAISS is a library: a fast in-memory ANN index with no metadata or persistence of its own. ChromaDB is a vector database: it persists to disk, filters on metadata, and stores documents. A local app that ingests PDFs needs persistence and metadata, so it uses Chroma. A standalone retrieval demo only needs fast search, so it uses FAISS.

Why all-MiniLM-L6-v2?

It produces 384-dim vectors, is small (~80 MB), runs fast on CPU, and works well for semantic similarity. The trade-off is lower quality than larger models such as bge or e5, and a 256-token input limit.

How would you evaluate RAG quality?
  • Retrieval: recall@k and MRR on a small labelled set of question-to-chunk pairs.
  • Generation: faithfulness (is the answer grounded in the context?) and answer relevance.
  • Tools: RAGAS, or LLM-as-judge plus manual spot checks.
Why run locally with Ollama? What is the trade-off?

Patient data is sensitive: running locally means no data leaves the machine, there is no API cost, and it works offline. The trade-offs are slower inference on CPU, and a small 3B model that is weaker at reasoning and SQL than GPT-class models.

What makes it "multi-agent" and not an if/else?

Each agent has its own role, prompt, and tools (SQL executor vs retriever), and the routing decision is made by an LLM rather than hard-coded rules. Be honest that it is a simple router pattern, not autonomous agents negotiating. Interviewers respect that.

2. Lip Reading Pipeline

Why 3D-CNN over 2D-CNN?

A 2D convolution sees one frame at a time. A 3D kernel (time × height × width) convolves across neighbouring frames, so it captures lip motion and not only shape.

Why a Bidirectional LSTM?

Speech depends on context on both sides. A sound is easier to identify when you know what comes before and after it. A BiLSTM reads the sequence forward and backward and concatenates both hidden states.

Explain CTC loss. Why use it here?

You have 75 frames but a much shorter transcript, with no per-frame labels. CTC adds a blank token and sums the probability over every alignment that collapses to the target text (merge repeats, then remove blanks). It needs no manual segmentation. Decoding uses greedy or beam search.

What are WER and CER? Is 32% good?

WER = (substitutions + deletions + insertions) / number of reference words. CER is the same at character level. LipNet reported a few percent WER on GRID with heavy tuning, so 32% is a reasonable student result, not state of the art. Ways to improve it:

  • More training epochs and data augmentation (flips, frame jitter).
  • Beam search with a language model.
  • A pretrained visual frontend or a transformer.
Why grayscale and a 112×112 crop?

Colour adds little information for lip shape, and grayscale cuts the input to a third. A tight mouth ROI removes irrelevant face and background pixels, cuts compute, and helps the model focus. Normalizing (mean/std) stabilizes training.

How did you locate the lips? Was this your own design?

Your code uses a fixed crop, gray[190:302, 80:192], because GRID speakers sit in a fixed position. For real-world video you'd add landmarks (dlib points 48–67 or MediaPipe). If the design was inspired by LipNet, say so. Claiming an original architecture that you cannot defend is worse.

How does JWT work?

There are three base64url parts: header.payload.signature. On login the server signs the payload (user id, role, expiry) with a secret key. The client sends Authorization: Bearer <token>, and the server verifies the signature, so it needs no session store (stateless). The payload is encoded, not encrypted, so never put secrets in it. Storage options: an httpOnly cookie is safer against XSS, while localStorage is simpler.

What does an ORM give you, and what is its downside?

Pros: Python objects in place of raw SQL, DB portability (SQLite to Postgres), parameterized queries that prevent SQL injection, and relationships. Cons: hidden inefficient queries (the N+1 problem), less control, and overhead on complex queries.

How are passwords stored?

They are hashed with bcrypt (passlib), which is salted and deliberately slow. Never store plain text, and never use bare MD5 or SHA for passwords.

4. CEI Internship & Kaggle

R² of 0.9983 is suspiciously high. Did you check for leakage?

This is the most likely trap. A good answer:

  • I used a time-ordered split (train on the past, test on the future), not a random split.
  • Lag features use only past values (shift(1)), so no current or future value leaks in.
  • Delivery data is highly autocorrelated, so lag-1 alone explains most of the variance. I compared against a naive baseline ("next = last value").

If you did not do these, admit it and explain how you would fix it.

Why lag features?

Tree models such as XGBoost have no notion of time order. Lag and rolling features (t-1, t-2, rolling mean) turn a time series into a supervised table that the model can learn from.

K-Means vs DBSCAN vs Hierarchical: when do you use each? How do you choose k?

K-MeansSpherical clusters and a known k; it is fastSensitive to scale and outliers; k must be set

To choose k, use the elbow method (inertia) or the silhouette score. Scale features first.

CIFAR-10 at 81.9%: how would you raise it?

Data augmentation (flip, crop), BatchNorm, dropout, a deeper network or ResNet blocks, LR scheduling, and transfer learning from ImageNet weights. Each can push accuracy above 90%.

RNN vs LSTM vs GRU: what is the vanishing gradient problem?

A plain RNN multiplies gradients through time steps, so they shrink toward zero and it cannot learn long dependencies. An LSTM adds a cell state with input, forget, and output gates, so gradients flow additively. A GRU merges these into update and reset gates: fewer parameters, faster, and often similar accuracy.

What is an autoencoder? What does a denoising autoencoder do?

An encoder compresses the input to a bottleneck and a decoder reconstructs it; training minimizes reconstruction loss. A denoising autoencoder takes noisy input and learns to output the clean original. This forces it to learn robust features rather than the identity function.

Kaggle: why Macro F1 and not accuracy?

Anomalies are rare. A model that predicts "normal" every time gets high accuracy but is useless. Macro F1 averages F1 per class equally, so the minority class counts the same as the majority class.

Did you apply SMOTE before or after the split?

It must be after, on the training fold only (use an imblearn Pipeline inside CV). If you oversample before the split, synthetic points derived from test samples leak into training and inflate the score.

How did you tune the threshold?

The default threshold of 0.5 is not optimal for imbalanced data. I swept thresholds on the validation set's predicted probabilities and picked the one with the highest F1. Never tune on the test set.

XGBoost vs LightGBM?

Both are gradient-boosted trees. XGBoost grows trees level-wise. LightGBM grows them leaf-wise with histogram binning, so it is faster on large data but can overfit small data (limit num_leaves). An ensemble of the two reduces variance.

*args and **kwargs

*args collects extra positional arguments into a tuple. **kwargs collects extra keyword arguments into a dict. Both are used for wrappers and decorators that forward any arguments.

Write a decorator (timer) 
import time, functools
def timer(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        t = time.perf_counter()
        result = fn(*args, **kwargs)
        print(f"{fn.__name__}: {time.perf_counter() - t:.4f}s")
        return result
    return wrapper

@timer
def work(): sum(range(10**6))
Generators: what does yield do?

A function that uses yield returns an iterator that produces values lazily, one at a time, keeping its state between calls. It uses O(1) memory, compared with building a full list. Use it for large files and streams. A generator expression looks like (x*x for x in data).

What is the GIL? Threading vs multiprocessing vs asyncio

The Global Interpreter Lock lets only one thread run Python bytecode at a time.

  • threading: suits I/O-bound work, because the GIL is released while waiting.
  • multiprocessing: suits CPU-bound work. Separate processes give true parallelism.
  • asyncio: one thread with cooperative multitasking, for many concurrent I/O tasks (FastAPI async routes).
try / except / else / finally

else runs only if no exception was raised. finally always runs, so use it for cleanup. Catch specific exceptions, not a bare except:.

__str__ vs __repr__

__str__ is the readable form for users (print). __repr__ is the unambiguous form for developers, ideally valid code that recreates the object. If only __repr__ is defined, str() falls back to it.

What does with do?

It is a context manager: it calls __enter__ at the start and __exit__ at the end, even on an exception. That guarantees cleanup such as closing a file or releasing a lock. contextlib.contextmanager builds one from a generator.

How does Python manage memory?

Through reference counting: an object is freed when its count reaches 0. A cyclic garbage collector handles reference cycles. Small ints and some strings are cached (interned).

6. OOP

Explain the four pillars with Python examples.
  • Encapsulation: bundle data and methods, and hide internals (_balance, properties).
  • Abstraction: expose what an object does, not how (an abc.ABC with @abstractmethod).
  • Inheritance: class Admin(User) reuses and extends the parent.
  • Polymorphism: one interface with many forms. shape.area() works for Circle and Square; duck typing.
Overloading vs overriding in Python

Overriding: a child class redefines a parent method, and can call super(). Python has no true overloading: a later definition replaces an earlier one. Use default arguments, *args, or functools.singledispatch. Operator overloading works through dunder methods (__add__).

@staticmethod vs @classmethod

A classmethod receives cls and is used for alternative constructors (Date.from_string()). A staticmethod receives neither self nor cls: it is a utility function grouped under the class.

Multiple inheritance and MRO (the diamond problem)

Python resolves methods with C3 linearization. Inspect the order with Class.__mro__. With class D(B, C) and both inheriting A, the order is D, B, C, A, so A is visited once. super() follows the MRO.

Is encapsulation real in Python?

Only by convention. _x means "internal, please don't touch". __x triggers name mangling to _Class__x to avoid subclass clashes. Nothing is truly private. Use @property for controlled access.

Two Sum 
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i

O(n) time, O(n) space. Brute force is O(n²).

Valid parentheses 
def valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for c in s:
        if c in pairs:
            if not stack or stack.pop() != pairs[c]:
                return False
        else:
            stack.append(c)
    return not stack

O(n) time, O(n) space.

def reverse(head):
    prev = None

        head.next, prev, head = prev, head, head.next
    return prev

Maximum subarray sum (Kadane's algorithm) 
def max_subarray(nums):
    best = cur = nums[0]
    for n in nums[1:]:
        cur = max(n, cur + n)
        best = max(best, cur)
    return best

O(n) time, O(1) space.

Longest substring without repeating characters (sliding window) 
def longest(s):
    last, start, best = {}, 0, 0
    for i, c in enumerate(s):
        if last.get(c, -1) >= start:
            start = last[c] + 1
        last[c] = i
        best = max(best, i - start + 1)
    return best

O(n) time.

Binary search 
def bsearch(a, x):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x: return mid
        if a[mid] < x: lo = mid + 1
        else: hi = mid - 1
    return -1

O(log n) time. The array must be sorted. The stdlib has bisect.

def level_order(root):
    q, out = deque([root] if root else []), []
    while q:
        node = q.popleft(); out.append(node.val)
        if node.left: q.append(node.left)
        if node.right: q.append(node.right)

Merge two sorted arrays 
def merge(a, b):
    i = j = 0; out = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]: out.append(a[i]); i += 1
        else: out.append(b[j]); j += 1
    return out + a[i:] + b[j:]

O(n + m) time.

Common complexities to know

Sorting (Timsort): O(n log n). Dict and set lookup: O(1) average. List in: O(n). List append: O(1) amortized. list.insert(0, x): O(n), so use deque. Heap push and pop: O(log n).

WHERE vs HAVING

WHERE filters rows before grouping. HAVING filters groups after GROUP BY and can use aggregates.

SELECT dept, AVG(salary) FROM employee
WHERE active = 1 GROUP BY dept HAVING AVG(salary) > 50000;
Types of JOIN

INNER: only matching rows. LEFT: all left rows, with NULL where the right has no match. RIGHT: the mirror of LEFT. FULL OUTER: all rows from both. CROSS: the Cartesian product. SELF: a table joined to itself.

Normalization: 1NF, 2NF, 3NF
  • 1NF: atomic values, no repeating groups.
  • 2NF: 1NF, and no partial dependency on part of a composite key.
  • 3NF: 2NF, and no transitive dependency (a non-key column depending on another non-key column).

The goal is to remove redundancy and update anomalies. You may denormalize for read speed.

ACID properties

Atomicity: all or nothing. Consistency: constraints always hold. Isolation: concurrent transactions don't interfere. Durability: committed data survives a crash.

What is an index? When does it hurt?

An index is usually a B-tree on a column, and turns lookups from O(n) into O(log n). It hurts write-heavy tables, because every INSERT or UPDATE must also update the index. It adds storage, and does little on low-cardinality columns.

Primary key vs unique key vs foreign key

PK: unique and NOT NULL, one per table. Unique: no duplicates, NULL allowed, many per table. FK: references another table's PK and enforces referential integrity.

DELETE vs TRUNCATE vs DROP

DELETE: removes rows, can take a WHERE, is logged, can be rolled back. TRUNCATE: removes all rows quickly and keeps the structure. DROP: removes the table itself.

SQL vs NoSQL. Where does a vector database fit?

SQL means a fixed schema, relations, ACID, and joins. NoSQL (document, key-value, graph) means a flexible schema and horizontal scaling. A vector database (Chroma, FAISS, pgvector) stores embeddings and answers similarity search rather than exact matches.

9. ML Fundamentals

Supervised vs unsupervised vs reinforcement learning

Supervised: labelled data (regression, classification). Unsupervised: no labels; find structure (clustering, PCA). Reinforcement: an agent learns from rewards by interacting with an environment.

Bias-variance trade-off and overfitting

High bias means underfitting: the model is too simple. High variance means overfitting: it memorizes noise, scoring well on train and badly on test. Fixes for overfitting: more data, regularization (L1/L2), dropout, early stopping, a simpler model, and cross-validation.

Precision, recall, F1, ROC-AUC

Precision = TP / (TP + FP): of the predicted positives, how many are correct. Use it when false positives are costly, as in spam filtering. Recall = TP / (TP + FN): of the actual positives, how many were found. Use it when misses are costly, as in disease or anomaly detection. F1 is their harmonic mean. ROC-AUC measures ranking quality across all thresholds. Prefer PR-AUC when classes are heavily imbalanced.

Bagging vs boosting

Bagging (Random Forest): trees are trained in parallel on bootstrap samples and averaged, which reduces variance. Boosting (XGBoost): trees are trained sequentially, each fixing the previous one's errors, which reduces bias. Boosting is often more accurate but easier to overfit.

Train/val/test split and cross-validation

Train fits the model, validation tunes hyperparameters, and test is a final one-time estimate. K-fold CV rotates the validation fold. Use stratified K-fold for imbalanced data and TimeSeriesSplit for time series.

Gradient descent and learning rate

Gradient descent updates weights against the gradient of the loss: w = w - lr * dL/dw. If the learning rate is too high, training diverges; too low, it is slow. Variants: SGD, mini-batch, and Adam (adaptive per-parameter rates).

Why ReLU?

It is cheap and does not saturate for positive inputs, so it avoids the vanishing gradients of sigmoid and tanh. Its weakness is "dying ReLU" (neurons stuck at 0), which Leaky ReLU fixes. Use softmax at the output for multi-class and sigmoid for binary.

How do you handle imbalanced data?

Use class weights, resampling (SMOTE or undersampling, on train only), threshold tuning, and the right metric (F1, PR-AUC).

10. GenAI / LLM / RAG / Agents

What is an LLM? Explain attention briefly.

An LLM is a transformer trained to predict the next token on huge text corpora. Self-attention lets each token weigh every other token: softmax(QKᵀ/√d)·V. This captures context in parallel, unlike an RNN.

Tokens and context window

A token is a sub-word unit, about 4 characters of English. The context window is the maximum number of tokens the model can see at once (prompt plus output). Anything beyond it is lost, which is one reason RAG retrieves only the relevant chunks.

What are embeddings? What is cosine similarity?

An embedding is a dense vector in which semantically similar text lies close together. Cosine similarity = (A·B) / (|A||B|), the angle between vectors, ranging from -1 to 1. It is used to rank retrieved chunks.

RAG vs fine-tuning

RAG suits changing or private knowledge and needs citations. It requires no training and the data can be updated instantly. Fine-tuning changes behaviour, style, or format, or teaches a narrow task. It does not reliably add facts and is costly. They are often combined.

How does vector search scale? (ANN)

Exact search compares against every vector, which is O(n). Approximate nearest neighbour indexes are much faster for a small accuracy loss:

  • HNSW: a graph index (Chroma uses it).
  • IVF: clusters the vectors and searches only the nearest clusters.
  • PQ: compresses vectors (FAISS offers all of these).
Temperature and top-p

Temperature scales the logits: near 0 output is deterministic, which suits SQL and JSON; higher is more creative. Top-p (nucleus) samples only from the smallest set of tokens whose cumulative probability reaches p.

Prompting techniques

Zero-shot: instructions only. Few-shot: include examples. Chain-of-thought: ask for step-by-step reasoning. Also useful: system role prompts, output format constraints, and delimiters around the context.

What is an AI agent? What is ReAct?

An agent is an LLM that decides which tools to call (search, SQL, API), observes the results, and loops until done. ReAct means Reason, then Act, then Observe, repeated. The parts are the LLM, the tools, memory, and a planner or loop.

What does LangChain give you? Could you work without it?

It provides ready-made loaders, splitters, vector-store wrappers, prompt templates, chains, and agents, so you prototype quickly. Its downsides are heavy abstraction and API churn. Yes, you could build without it: a RAG pipeline is about 50 lines (embed, search, format prompt, call LLM). Saying this shows you understand what happens underneath.

What is hallucination? How do you reduce it?

Hallucination is confident but false output. To reduce it: use RAG grounding, add "answer only from the context, otherwise say you don't know", lower the temperature, cite sources, and validate outputs.

What is prompt injection?

Malicious instructions arrive in user input or in retrieved documents ("ignore previous instructions..."). Mitigations: least-privilege tools (a read-only DB), input and output validation, separating the system prompt from data, and human approval for risky actions.
